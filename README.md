# Hackathon

A starter web project with a separated frontend and backend:

- **Backend** — FastAPI (Python) + SQLite, in Docker, on http://127.0.0.1:5001
- **Frontend** — Bootstrap 5.3 (plain HTML/CSS/JS), on http://127.0.0.1:3001

## Structure

```
run-backend.sh      — start the backend in Docker (build, DB volume, hot reload)
run-frontend.sh     — start the frontend (plain static server, no deps)
backend/
  main.py           — FastAPI app: JSON API + SQLite, CORS enabled for the frontend
  requirements.txt  — Python dependencies
  Dockerfile        — container build for the backend
  .env.example      — copy to .env for secrets/config
  app.db            — SQLite database (created on first run, gitignored)
frontend/
  index.html        — Bootstrap page
  css/style.css     — custom styles
  js/main.js        — calls the backend API with fetch (API_BASE at the top)
```

## Run (two terminals, Docker must be running)

```sh
./run-backend.sh      # terminal 1 — builds the image and starts the container
./run-frontend.sh     # terminal 2 — optional port argument, e.g. ./run-frontend.sh 8080
```

Then open http://127.0.0.1:3001. The demo creates, lists, and deletes items
through the API, stored in SQLite.

The backend container mounts the source code, so edits to backend/ hot-reload
without a rebuild. The SQLite DB lives in the `hackathon-db` Docker volume and
survives restarts. Rebuilds happen automatically on each start (fast when
nothing changed); only requirements.txt changes make it slow.

Interactive API docs (auto-generated by FastAPI): http://127.0.0.1:5001/docs

## API

- `GET /api/health` — liveness check
- `GET /api/items` — list items
- `POST /api/items` — create an item, JSON body: `{"name": "..."}`
- `DELETE /api/items/{id}` — delete an item

Example:

```sh
curl -X POST http://127.0.0.1:5001/api/items \
  -H 'Content-Type: application/json' \
  -d '{"name": "first item"}'
```
